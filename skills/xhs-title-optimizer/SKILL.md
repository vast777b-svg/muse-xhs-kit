# 小红书标题优化

小红书标题的硬限制：**最多 20 个中文字符**（emoji 按多字符算）。在这个笼子里做到高点击，靠的是结构，不是形容词堆砌。

## 一、先诊断，再改

拿到原标题，先判断它病在哪一类：

| 症状 | 表现 | 病因 |
|---|---|---|
| **平** | 陈述事实，没有情绪落差 | 缺少冲突或反差 |
| **散** | 说了三件事，每件都不深 | 没有单一焦点 |
| **虚** | "干货满满""必看" | 没有具体对象 |
| **假** | "震惊""绝了"但内容普通 | 情绪与内容不匹配 |
| **长** | 超过 20 字被截断 | 没做压缩 |
| **自嗨** | 讲"我"的感受，不讲读者的收益 | 视角错位 |

改之前先把诊断结论告诉用户，不要直接甩一个新标题。用户要知道**为什么**这么改。

## 二、五种可复用的标题骨架

每种给 2-3 个变体，让用户挑。不要只给一个答案。

### 骨架 A｜情绪词 + 具体对象

> 被 claude 惊到了
> 这个东西我真香了

**适用**：体验类、工具类、探店。
**关键**：情绪词必须和后面的具体对象形成落差。空喊"绝了"无效。

### 骨架 B｜反差 / 否定预期

> 别再迷信一键起号了
> 我劝你不要买这款
> 花 3000 买的教训，免费给你

**适用**：避坑、复盘、反主流观点。
**关键**：否定的是读者的**既有认知**，不是同行。

### 骨架 C｜数字 + 时间 + 结果

> 3 个月从 0 到 5000 粉，只做对一件事
> 改了 5 版封面，点击率翻倍

**适用**：方法论、成长记录、数据复盘。
**关键**：数字要具体且可信。虚数（"迅速""大幅"）会削弱可信度。

### 骨架 D｜身份 + 场景 + 痛点

> 干皮冬天上妆卡粉？我找到解法了
> 租房党必看：300 块改造出租屋

**适用**：垂直人群、具体场景。
**关键**：身份和痛点要窄，窄才精准。写给"所有人"等于写给没人。

### 骨架 E｜提问 / 悬念

> 为什么我用了三年才懂这个道理
> 这个功能 90% 的人不知道

**适用**：认知类、教程类。
**关键**：问题必须是读者**真的会问自己**的问题。自造疑问无效。

## 三、20 字压缩法

标题超长时按这个顺序砍：

1. **砍虚词**：那些、真的、其实、非常 → 删
2. **砍铺垫**：今天想跟大家分享 → 删
3. **砍重复**：两个近义形容词留一个
4. **换短词**：「进行优化」→「优化」；「的使用体验」→「体验」
5. **数字替词**：「很多次」→「5 次」
6. **必要时换骨架**：如果砍完还是超，说明这个标题承载了太多，换一个更聚焦的角度重写

## 四、从爆款反推骨架

用户给一个爆款链接或标题时：

1. **拆结构**：它是哪个骨架？哪部分是钩子？
2. **拆词性**：情绪词在哪、具体对象在哪、数字在哪
3. **替换变量**：保留骨架，换成用户自己的领域和素材
4. **检查是否套得太死**：如果只有名词换了，读起来会很假，需要调整语序

**不要抄原文**。抄结构不抄词，这是借鉴和洗稿的分界线。

## 五、标题 + 正文 + 标签的联动

标题定了，正文第一句必须承接标题的钩子，否则读者点进来就划走。

- 标题问问题 → 正文第一句给半个答案
- 标题给结论 → 正文第一句给场景
- 标题制造反差 → 正文第一句解释反差从哪来

标签建议 5-8 个：2 个大词（品类）+ 3 个精准词（人群/场景）+ 1-2 个长尾词。不要堆 20 个。

## 六、产出格式

给用户的输出固定成这个结构：

```
原标题诊断：<病在哪>
改后方案：
  A（骨架 X）标题一行
  B（骨架 Y）标题一行
  C（骨架 Z）标题一行
推荐：<哪个，为什么>
正文首句承接：<一句话>
```

## 边界

- 标题优化是**提高点击的正当手段**，不是骗点击。内容撑不住的标题，短期涨点击、长期掉权重。
- 优化后的标题**必须再过一遍** `xhs-compliance-check`，因为极限词（最好、第一）常出现在标题里。
- 标题超过 20 字会被平台截断，永远不要赌"它会显示全"。
