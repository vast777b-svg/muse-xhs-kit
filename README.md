# Muse 小红书工具包

给 Muse（云端 Ubuntu）用的小红书工作流三件套 + 可选自动发布。

**设计原则：默认全离线、不碰账号。** 想发布才装发布组件，装了也留人工闸门。

---

## 装什么

### 基础包（不碰账号，零风险）

| Skill | 干什么 |
|---|---|
| `xhs-compliance-check` | 违规词检测。8 类词库 + 联系方式/外链识别，纯本地 |
| `xhs-title-optimizer` | 标题优化。诊断病灶 + 5 种骨架 + 20 字压缩法 |
| `xhs-viral-remix` | 爆款拆解（5 层模型）+ 原创仿写 + 洗稿红线判定 |

### 可选包（`--with-publish`，要操作真实账号）

`xiaohongshu-mcp` Linux 二进制：登录、发布图文/视频、搜索、评论、点赞、收藏。

---

## 安装

```bash
# 只装不碰账号的部分（推荐先这样）
bash install.sh

# 额外装自动发布
bash install.sh --with-publish
```

装完的目录：

```
~/.claude/skills/xhs-compliance-check/
~/.claude/skills/xhs-title-optimizer/
~/.claude/skills/xhs-viral-remix/
~/xhs/
├── drafts/      文案草稿
├── patterns/    爆款拆解记录
└── output/      生成的图
```

## 手动步骤清单

### 基础包 — 全程自动，无手动步骤

装完就能用。

### 自动发布（`--with-publish`）— 有 4 处必须你本人操作

| # | 步骤 | 为什么必须手动 |
|---|---|---|
| **1** | 运行 `./xiaohongshu-login`，用手机小红书 App **扫码** | 二维码是一张图，Muse 拿不到你的手机；扫必须人来做 |
| **2** | 如触发**短信/人机验证**，手动完成 | 验证码只会发到你的手机 |
| **3** | 首次发笔记前，**人工通读文案** | 机器测不出"这话像不像人说的""会不会被误解" |
| **4** | 点击**发布**按钮前，人工确认 | 发出去收不回；定时发布同样要人确认 |

另外两个隐性手动点：

- **首次登录大概率失败一次** —— Muse 是机房 IP，小红书会判异地。正常，重试即可。反复失败说明 IP 段被标记了。
- **首次运行会下载 150MB 无头浏览器** —— 网络慢的话要等，别以为卡死了。

## 用法（对 Muse 说这些）

### 违规检测

```
帮我检查这段文案能不能发小红书：
<粘贴文案>
```

Muse 会调用 `check.py`，返回分级结果 + 替换建议。

### 标题优化

```
我这个标题点击率很低，帮我改：
<原标题>
```
或
```
我写了个小红书笔记，讲的是<主题>，受众是<人群>，帮我想 5 个标题
```

### 爆款拆解

```
拆解一下这个爆款：<链接或标题+正文>
它为什么火？我能不能写个类似的？
```

### 自动发布（装了才可用）

```
把 ~/xhs/drafts/xxx.md 这篇发到小红书
```

⚠️ Muse 应该会在点发布前停下来问你。**如果它没停，立刻叫停。**

## 安全边界

这台机器能碰到你真实的小红书账号，请守住这几条：

| 红线 | 说明 |
|---|---|
| ❌ 不要关掉人工闸门 | 第 3、4 步是防止误发的唯一保险 |
| ❌ 不要批量高频发布 | 一天超过 3 篇是平台风控首要信号 |
| ❌ 不要在凌晨自动跑 | 行为模式异常会拉高账号风险分 |
| ❌ 不要把 cookie/登录态贴进对话 | 会被记录到会话历史 |
| ✅ 先用小号试 | 验证流程跑通再上主号 |

详细的 A/B/C 三层风险分级见 [RISK-LEVELS.md](RISK-LEVELS.md)。
